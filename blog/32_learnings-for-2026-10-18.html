Tools that write files the builder gets blamed for

Folders inside a change crashed the checks, a fork had no main branch, and a held job waited on a fix that had already landed.

Submodule folders crashed the rails

What happenedThe Foundry scaffold committed lib/ submodules, and the pre-review rails opened every changed path as a file and threw EISDIR

LessonA diff can contain folders, so any rail that reads changed paths has to skip gitlinks

What changedStep 2 and the pre-review rails now skip mode-160000 entries

Hardcoded main on a master-only fork

What happenedOn the hts-specs job the rails ran gh compare against main, a branch the fork does not have, so every run returned 404 whatever the code was

LessonNever assume the branch name; read the fork's default branch

What changedThe rails and the PR opener now use the fork's default branch

Tools write files the builder is blamed for

What happenedForge wrote foundry.lock during the build, and the authority rail refused a span no builder wrote

LessonFiles a tool writes on its own, like foundry.lock, medusa.json or a gitignored uv.lock, are not the builder's edits

What changedForge's lock file is dropped before pre_review, the fizz seat may write its root outputs, and the fence check ignores gitignored untracked files

A ruling barred the seat's only command

What happenedA director ruling barred uv run and asked for a delete the no-shell seat cannot do, so every round ran into the build cap

LessonA ruling has to fit what the seat is allowed to run

What changedThe next ruling allowed uv run --no-project, and seats can now delete files through ## Deleted

A held job waited on a fix already landed

What happenedThe fizz generator job was held twice for a missing null_check.py after the score step had already been fixed to skip it

LessonCheck main before holding a job on a fault

What changedNone yet: a hold's reason is not checked against main
