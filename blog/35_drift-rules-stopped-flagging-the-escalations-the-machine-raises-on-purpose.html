Drift rules stopped flagging the escalations the machine raises on purpose

Work completed 2026-10-21 · written up 2026-10-22.

A drift entry counted a designed escalation

The fork_actions_off entry counted the escalation the machine raises for every new fork with Actions off, so a correct escalation showed up as drift [landed:1557]

A drift rule that expects zero of a designed event can never hold

The entry now flags only a fork left with Actions off for over a day

ci.unrun written on every tick

The tick wrote ci.unrun on every tick while a fork job waited, and the fork_unrun rule treated that passing fallback as drift [landed:1558]

A fallback that passes is not drift, and one event per wait is enough

ci.unrun is written once per head sha and the rule expects the volume the tick really writes

A quote split in two

A research answer was refused again and again because the check split two quotes into separate sentences, the #845 quote at ". I" and the #189 quote at "? C", so the first half of each had no source [refusal:2313]

A sentence splitter that ignores quote marks refuses a quote copied word for word

A quote that fails the check twice in a row becomes a plain statement with its URL

No lane could reach the network

Asks that needed live HTTP calls sat on seats with no shell or network, so every rerun gave the same answer [landed:1577]

An ask that needs the network stalls if no lane can reach it

A new lane runs a script with outbound network access and writes its output to a declared folder under ~/cf_work/

The builder could not delete a file

A ticket to retire a registry entry was refused run after run because the builder seat cannot delete the file [refusal:2275]

A ticket whose whole change is a deletion stalls on a seat that can only edit

Filed as its own ticket so retire tickets can pass review
