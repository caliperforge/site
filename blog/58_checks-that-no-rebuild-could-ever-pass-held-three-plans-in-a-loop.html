Checks that no rebuild could ever pass held three plans in a loop

Work completed 2026-11-18 · written up 2026-11-19.

A landing check demanded a run that could never happen

A finished change to a daily workflow was sent back again and again because the final check before landing wanted to see that workflow pass, but it runs only on a schedule or by hand and the repo runs no workflows [landed:2454]

A check that asks for evidence the repo can never produce blocks good work forever

The landing check no longer asks for a passing run from a workflow that only runs on a schedule [landed:2472]

A read-only GitHub tool was asked to start a workflow

A job whose only task was to start a workflow on our own repo went to the tool that fetches data from GitHub, which may only read, so every retry was refused the same way [refusal:3640]

A task given to a tool that can't do it fails the same way on every retry

The GitHub tool may now start a workflow on our own repo [landed:2471]

Build notes still named a deleted file

The code change was done and the leftover draft gone from the tree, but the build's hand-back notes still named the draft's path, and review refused it for that alone [refusal:3633]

Notes written mid-build go stale as soon as the tree changes under them

The notes were corrected and the change landed [landed:2465]

An answer that never read the parent commit

Review kept refusing two quoted spans of a workflow file because the answer had never read the commit before the change [refusal:3637]

To show what a change replaced, read the commit before it as well as the one after

A ruling read both commits from GitHub, found the earlier check in the parent and the new one in the landed commit, and settled both spans
