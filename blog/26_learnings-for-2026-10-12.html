Rules that blocked the work they were meant to guide

Rulings were dropped for naming a file path, a check linked an out-of-date package, and a ruled file sat outside what the builder could write.

Rulings dropped for naming a path

What happenedThe director's rule guard dropped whole rulings because they named the plan's own new file or a public repo read at a fixed commit, which sent three jobs to the COO

LessonA guard that drops a whole ruling over one path costs more than the path it blocks

What changedThe guard now accepts a ruling that names the plan's own files or a public repo read at a fixed commit

Checks linked a stale crate

What happenedChecks refused the same E0599 build after build, though the method was defined ungated in the tree

LessonA shared cargo target dir links stale crates across checkouts, so a correct diff can still fail checks

What changedChecks build into a per-job CARGO_TARGET_DIR

A ruled file stayed outside write_paths

What happenedThe write-path gate refused, six times in a row, a file that the standing ruling required

LessonA ruling that names a file does not open it to the builder unless the gate reads the ruling

What changedseat.write_paths now widen to files a director or COO ruling names

The audit cannot read a valid handback

What happenedThe completion audit refused a handback that met every case, once as a list and once as a map with line pointers

LessonWhen two valid shapes are both refused, the fault is in the gate, and another rewrite only repeats the refusal

What changedNone yet: the job is parked until the audit reads case IDs and pointers from the fence

The ready gate lacks a token scope

What happenedThe ready gate's call to list the fork's Greptile repositories got HTTP 403 twice

LessonA gate that calls an API needs its token scopes checked before the gate runs, not after it refuses

What changedNone yet: the CEO has been asked to add read:user to the host gh login
