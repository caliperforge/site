When the checker breaks, the code gets blamed

A checking machine failed and the change took the blame; a finished research job held up the jobs queued behind it.

The checker host failed, not the diff

What happenedA pair-runner build was refused again because the checker host had no forge on PATH and no pytest for python3.15

LessonA refusal caused by the host tells you nothing about the diff, and rebuilding will not clear it

What changedNone yet: the job is parked until the checker environment is fixed

A finished research job held its followers

What happenedAccount-file jobs were held because their research ticket closed without any code landing, although the research job was done

LessonResearch has no code to land, so being done has to count as met

What changedA done research job now counts as met, so jobs waiting on it go ahead

The web drift check watched the wrong column

What happenedThe web_specialist drift check matched runs.seat, but web_specialist only ever appears in runs.staffed, so its finding was false

LessonA check that never matches reports drift that never happened

What changedThe web entry now reads runs.staffed

A correct build refused for a dropped row

What happenedThe final check refused a correct build because the latest build report overwrote the earlier one and dropped the row for sequencer/accounts.ts

LessonA report that replaces the last one can lose work the code still contains

What changedThe director ruled the code correct and the job landed

Language review checks fired on old work

What happenedThe Swift review check matched runs.seat and any plan that ever had a Swift file, so it fired whenever a week passed without Swift work

LessonA check gated on all history stays on and keeps firing

What changedThe eight language review entries now read runs.staffed and fire only for open or recently run plans
