Yarn targets reach install, and each fix exposes the next stop

Work completed 2026-10-26 · written up 2026-10-27.

A yarn install path with no yarn

generate gained a yarn.lock install, but the next run exited 127 because yarn was not on the generate host [refusal:2798]

An install path only counts once the tool it calls is on the machine

generate runs yarn through npx yarn@1, since corepack is no longer bundled with the host's Node [landed:1821]

yarn's own error was thrown away

yarn@1 install exited 1 and the refusal dropped the lines naming the failing child, so the first guess blamed native builds that --ignore-scripts already skips [refusal:2805]

A refusal that cuts the tool's stderr sends the fix after the wrong cause

The refusal keeps yarn's full stderr [landed:1825], which showed a git pull failing on a GitHub-hosted dependency [refusal:2807], and bench.install now handles that case [landed:1826]

Review refused what the record gate required

The fix fence blocked brief rewrites

A ruling that only appends an answer leaves the old file list in charge

The fence no longer counts paths written inside issue.md as writes [landed:1819]
