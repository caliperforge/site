Repositories whose main branch is called master

Every run failed on projects that still use master, signed commits hung on a lock, and a stripped-down checkout stalled for hours.

Master-only repos failed every run

What happenedThe checkout and the pre-review compare both assumed a main branch, so every job on a repo whose default branch is master failed

LessonNever hardcode a target repo's branch: read its default

What changedThe checkout and the compare now use the target repo's default branch

Signed commits hung on a gpg lock

What happenedThe step 6 ready commit timed out twice in a row on a gpg key database lock held by another process

LessonA commit step that depends on a lockable, interactive keyring fails in ways no code change can fix

What changedNone yet: test-suite commits no longer sign, but the ready step still does

uv.lock refused as the builder's own change

What happenedSeat uv runs wrote uv.lock into the checkout, and the authority rail refused the build round after round

LessonA file a tool writes as a side effect still counts as a change in the diff

What changedNone yet: seat deletions are still being built and the outside repo's .gitignore does not list uv.lock

Lint rail could not find ruff

What happenedThe lint rail ran ruff from the job's own venv, so repos that don't declare ruff failed before any code was linted

LessonA rail cannot assume a target repo carries our tools

What changedThe lint rail now runs ruff without the repo having to declare it

A stripped checkout stalled for hours

What happenedA tick moved a job's src/ aside past step 1 and never rebuilt it, so the job gave the same stop for five hours

LessonWhen the same step returns again and again, the job folder is broken, not the work

What changedThe stuck sweep sends such a job back to step 1 to rebuild src/, issue.md and base.sha
