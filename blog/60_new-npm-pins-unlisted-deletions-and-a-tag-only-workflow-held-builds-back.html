New npm pins, unlisted deletions and a tag-only workflow held builds back

Work completed 2026-11-20 · written up 2026-11-21.

No way in for a new npm dependency

The builder seat refuses npm install and the kernel ran only npm ci, so the attestation job was refused before it could add its pinned packages [refusal:3678]. Even after the installer landed, the job sat at step 3 and never went back through step 2 [landed:2489]

A job that needs new packages can't build until the machine installs them, and a fix only helps jobs that run back through the step where it lives

The kernel installs the rows under a brief's `## Pinned` heading before step 2. The brief got that section and went back to step 2 [landed:2487]

Deletions missing from the file list

The builder refused to delete two docs pages because the brief's `## Files` didn't list them [refusal:3677]

A move counts as a deletion, so the brief must list both the old path and the new one

The fixer added both deletions and the test path to `## Files`, and the retried build landed [landed:2486]

A test that passed without the fix

A rehearsal-lookup test passed with or without the fix, because its own reached() call reset the counter it checked [refusal:3679]

A test that stays green with the fix reverted proves nothing

The code_quality refusal was fixed in code and the job landed [landed:2488]

A test that skips the binding in the title

The ledger device-thread test never checks that the claim is freed before the reply, which is what the ticket's title promises [refusal:3684]

The test must assert the exact behaviour the title names

None yet: the job went back to step 2 to add one deterministic assertion and has not landed

A release workflow the ready gate can't see

release.yml ran only on tag pushes. After a pull_request trigger was added, the branch still had no open PR, so the ready gate saw no release run [refusal:3686]

A gate can only check a workflow whose trigger fires on the branch it inspects

Ruled that running the workflow on pull requests meets the ticket's dry-run requirement, because the tag check skips publishing there [landed:2491]
